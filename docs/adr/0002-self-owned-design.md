# ADR 0002 · 代码与玩法设计都归自己

- 状态：已认可（ADR 0000 第 6 节的展开）
- 日期：2026-11-12

## 背景

两个旧仓都源自 `czl9707/gh-space-shooter`。`cnb-space-invaders` 的 `constants.ts` 注明
「数值全部沿用上游 PyPI 2.0.5」，`strategies.ts` 注明「逐行对齐上游」；本项目的 README 也把
「格坐标 / `delta_time = 3.0/fps` / 分档血量」写成对参考项目的对齐。
也就是说：即使代码全是自己写的，**设计仍带着别人的形状**。用户明确要求「整个仓库都归属于我」。

## 决策

区分「实现」与「设计」，只继承前者里纯工程的那部分。

1. `domain/` 全部重写：自研「波次 + 热度 + 连击」规则，强度分档叫 `Tier` 而不是 `hp`，
   几何、配色、节奏、帧率全部自己定。不出现 `column` / `row` / `random` 策略名、
   `3.0/fps`、`860×230`、`hp=1..4` 等参考值。
2. `sources/` 只做协议归一，字段用中性语义名（见 `docs/02-contract.md`）。
3. `LICENSE` 只有 `h1s97x`；`NOTICE` 只写「灵感致谢」，不写「移植自 / 对齐上游」。
   `docs/04-rewrite-record.md` 用可核验方式记录「零代码继承」（例如列出未复制的上游文件清单）。
4. 主仓身份：CNB 唯一源，GitHub 仅 `uses:` 分发端点，单向同步。

## 后果

- 正面：归属从「声明」变成可核验的事实；后续可以任意改玩法，不必顾虑是否偏离参考。
- 负面：不能再宣称「与参考项目一致」；两个旧仓的用户会看到不同的 GIF，必须在
  `docs/05-migration.md` 里给出参数与观感的迁移说明。
- 验收：规则文件不含上游常量 / 策略名 / 参考节奏；`NOTICE` 无「移植」措辞。
